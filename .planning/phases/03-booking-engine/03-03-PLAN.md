    Export:
    - useBookings(): useQuery({ queryKey: ['bookings'], queryFn: () => bookingApi.getBookings().then(r => r.data) })
    - useAcceptBooking(): useMutation({ mutationFn: (id: string) => bookingApi.acceptBooking(id), onSuccess: () => { queryClient.invalidateQueries({ queryKey: ['bookings'] }); toast.success('Booking confirmed. A meeting link has been attached.'); }, onError: () => { toast.error('Something went wrong. Please try again.'); } })
    - useDeclineBooking(): same pattern, onSuccess toast: 'Booking declined.', mutation calls bookingApi.declineBooking

    - useCreateBooking(): mutationFn calls bookingApi.createBooking, onSuccess toast: 'Request sent — awaiting approval.', onError: check 409 → toast.error('This time slot has already been booked. Please choose another.'), else generic error

    Use useQueryClient() from react-query for cache invalidation. Import it at top: import { useQueryClient } from '@tanstack/react-query';

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| React → GET /api/v1/bookings | Only returns bookings where caller is owner or booker — enforced server-side (Plan 03-01) |
| Meet URL link | External URL opened in new tab — must include rel="noreferrer" to prevent window.opener leakage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Information Disclosure | Meet URL in My Bookings | mitigate | rel="noreferrer" on all external Meet links — prevents referrer leakage and opener access |
| T-03-11 | Tampering | Cancel booking frontend | mitigate | Two-step inline confirmation prevents accidental click; server enforces 24h policy regardless |
| T-03-SC | Tampering | shadcn CLI registry install | accept | shadcn official registry only (Dialog/Badge/Tabs/Separator); no third-party registries per UI-SPEC |
</threat_model>
