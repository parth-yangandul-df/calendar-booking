## Color

Inherits shadcn CSS variable palette (neutral base). New semantic colors for booking status only.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` | Page surfaces, side panel background, modal backdrop |
| Secondary (30%) | `var(--card)` / `var(--muted)` | Booking list cards, tab container, `/bookings` page sections |
| Accent (10%) | `var(--primary)` | Confirm button in modal, "Accept Booking" button on Incoming tab only |
| Destructive | `var(--destructive)` | Decline button, Cancel booking button, 24h cancellation error |

### Booking Status Color Contract

> Source: D-29 (CONTEXT.md) — "Pending = yellow, Confirmed = green — distinct from plain availability color"
> Availability blocks already use `bg-green-100/border-green-300` (own) and `bg-blue-100/border-blue-300` (read-only). Booking colors MUST NOT collide.

| Status | Background | Border | Text | Tailwind Classes |
|--------|-----------|--------|------|-----------------|
| Pending | amber-100 | amber-300 | amber-800 | `bg-amber-100 border border-amber-300 text-amber-800` |
| Confirmed | emerald-100 | emerald-400 | emerald-800 | `bg-emerald-100 border border-emerald-400 text-emerald-800` |
| Declined | red-100 | red-300 | red-700 | `bg-red-100 border border-red-300 text-red-700` |
| Cancelled | zinc-100 | zinc-300 | zinc-500 | `bg-zinc-100 border border-zinc-300 text-zinc-500` |

> **Collision check:** Availability own = `green-100/300` → Confirmed booking uses `emerald-100/400` (visually distinct — emerald is deeper). Availability read-only = `blue-100/300` — no booking status uses blue. Availability override = `orange-100/300` — no booking status uses orange. ✅ No collision.

Accent reserved for: **"Request Booking" confirm button in modal**, **"Accept Booking" button on Incoming tab**.  
Never applied to: navigation links, availability blocks, read-only states, or decorative elements.

## Page & Surface Inventory

### 1. UserCalendarPage — Side Panel Extension (`DaySidePanel.tsx`)

The existing `DaySidePanel` (w-80, fixed right, slide-in) gains a **booking section** when viewing another user's calendar (read-only mode).

| Section | Content | Interaction |
|---------|---------|-------------|
| Header | Date heading (existing) | No change |
| Availability summary | Owner's available time ranges (existing read-only display) | No change |
| Timeline / Free-busy | Vertical list of time slots within the day's availability window: free blocks (white, dashed border) and booked blocks (amber/emerald colored) | Visual only |
| Duration picker | Segmented control or button group: **30 min**, **1 hr**, **2 hr**, **Custom** | Click selects duration |
| Start time picker | Dropdown or button list of valid start times (15-min increments within free blocks only) | Click selects start |
| Book button | "Request Booking" — primary, full width, disabled until start time + duration both selected | Opens confirmation modal |

**Timeline block anatomy** (free slot):
- Background: white / `var(--background)`, border: 1px dashed `var(--border)`
- Label: time range in 12px semibold
- Shows: "Available" label + time range

**Timeline block anatomy** (booked slot):
- Background + border per status color table above
- Shows: status chip + time range (no booker name visible to third parties)

### 2. Owner's Own Calendar — Side Panel Extension

When owner clicks a day on their own calendar that has bookings:

| Content | Condition | Actions |
|---------|-----------|---------|
| Pending booking block | Status = Pending | **Accept Booking** (primary), **Decline Booking** (destructive-outline) buttons |
| Confirmed booking block | Status = Confirmed | **Cancel Booking** (destructive-outline) button if >24h; disabled + tooltip "Within 24h" if ≤24h |
| Declined booking block | Status = Declined | Read-only, no actions |
| Cancelled booking block | Status = Cancelled | Read-only, greyed out |

**Destructive confirmation approach — "Cancel Booking":**  
Use **inline two-step confirmation** within the same card/panel row. On first click, "Cancel Booking" button is replaced by two inline buttons: **"Yes, cancel it"** (destructive solid) and **"Keep it"** (ghost). No modal, no toast undo. Rationale: the action is irreversible (slot freed immediately, emails sent); an undo toast would require a hold-period that conflicts with D-18's "slot freed immediately" requirement.

### 3. Booking Confirmation Modal (Dialog)

Triggered: Booker clicks "Request Booking" in side panel.

| Element | Spec |
|---------|------|
| Title | "Confirm your booking" |
| Body | "Book **[StartTime]–[EndTime]** with **[OwnerName]** on **[Day, Month D, YYYY]**?" |
| Sub-text | "Your request will be sent for approval." (14px, muted) |
| CTA | "Request Booking" — primary button, full width |
| Cancel | "Keep this time" — ghost/outline button, full width |
| Layout | Two stacked full-width buttons (mobile-first); CTA on top |
| Loading | CTA shows spinner + "Sending…", both buttons disabled during submission |

### 4. `/bookings` Page — Two-Tab Layout

| Element | Spec |
|---------|------|
| Page title | "Bookings" (20px semibold) |
| Tab: Incoming | Shows booking requests on owner's calendar (status: Pending by default) |
| Tab: My Bookings | Shows bookings the current user made elsewhere |
| Tab indicator | shadcn Tabs component, default underline style |

**Incoming tab — booking list item:**

| Element | Spec |
|---------|------|
| Layout | Card row: [Status badge] [Booker name + date/time] [Accept Booking / Decline Booking buttons] |
| Status badge | Pending: amber chip (see color table) |
| Accept Booking button | Primary (min-h 44px) |
| Decline Booking button | Destructive outline (min-h 44px) |
| Empty state | "No pending requests" (heading) + "When someone requests a booking on your calendar, it will appear here." |

**My Bookings tab — booking list item:**

| Element | Spec |
|---------|------|
| Layout | Card row: [Status badge] [Owner name + date/time + Meet URL if confirmed] [Cancel button if eligible] |
| Status badge | Per color table (Pending/Confirmed/Declined/Cancelled) |
| Meet URL | Only shown when Confirmed — "Join meeting" link (external, opens new tab) |
| Cancel button | Destructive outline, visible only when Confirmed + >24h; hidden otherwise |
| Empty state | "No bookings yet" (heading) + "Browse people's calendars to request a booking." + "Find people →" link to `/users` |

### 5. Month Grid Color-Coded Booking Blocks

Extends `MonthGrid.tsx` — new block variants rendered alongside availability ranges:

| Block type | Classes | Label |
|------------|---------|-------|
| Pending booking | `bg-amber-100 border border-amber-300 text-amber-800` | "Pending" |
| Confirmed booking | `bg-emerald-100 border border-emerald-400 text-emerald-800` | "Confirmed" |

These appear in day cells only on the owner's own calendar. On read-only `/users/{id}` view, booked slots appear as "Unavailable" blocks (no status label exposed to third parties) using `bg-zinc-100 border border-zinc-300 text-zinc-500`.

### 6. Navbar Extension

Add "Bookings" link to `Navbar.tsx` — routes to `/bookings`. Icon: `CalendarCheck` (lucide-react). Positioned after "My Calendar" link.

## Interaction States

| State | Behavior |
|-------|----------|
| Duration not selected | "Request Booking" button disabled |
| Start time not selected | "Request Booking" button disabled |
| Submitting booking | Button spinner + "Sending…", panel non-interactive |
| Booking success | Side panel closes, Sonner toast: "Request sent — awaiting approval." |
| Conflict (409) | Sonner toast error: "This time slot has already been booked. Please choose another." |
| Accept success | Row removed from Incoming list, Sonner: "Booking confirmed. A meeting link has been attached." |
| Decline success | Row removed from Incoming list, Sonner: "Booking declined." |
| Cancel success | Status badge updates to Cancelled, Sonner: "Booking cancelled." |
| Cancel denied — within 24h | Sonner toast error: "Cannot cancel within 24 hours of the booking." |
| Server error | Sonner toast: "Something went wrong. Please try again." |

## Accessibility Notes

- Accept Booking / Decline Booking / Cancel Booking buttons: `min-height: 44px` — WCAG 2.5.5 target size
- Disabled cancel button within 24h window: include `title` tooltip with reason text
- Confirmation modal: focus trapped inside Dialog while open (shadcn Dialog handles this via Radix)
- Status badges: do not rely on color alone — always include text label
- Booking block tooltips (month grid): on hover, show full "Pending: 10:00–11:00 with John Doe" via `title` attribute
- `aria-label` on side panel close button: "Close" (already in DaySidePanel.tsx line 82 — maintain)
