       - `UpdateAsync(RefreshToken token)`: `_context.RefreshTokens.Update(token); await _context.SaveChangesAsync()`
       - `RevokeAllForUserAsync(string userId)`: Find all non-revoked tokens for userId, mark IsRevoked=true, save

       - Check if admin exists via `FindByEmailAsync` — if yes, return early (idempotent)

         - Validate RegisterRequest via injected validator (throw ValidationException on failure)

         - Return 400 if creation fails (ProblemDetails with errors from `result.Errors`)
         - Return 200 with `AuthResponse { Email = user.Email, IsAdmin = false }`

       - **POST /login**:
         - Validate LoginRequest via injected validator
         - Find user by email: `UserManager.FindByEmailAsync(request.Email)`
         - If null or password check fails: return 401 with ProblemDetails "Invalid email or password. Please try again." (per UI-SPEC copy)

         - Set two httpOnly cookies (per D-04/D-05):
           - `AccessToken`: value = accessToken, HttpOnly=true, Secure=true, SameSite=Strict, Expires=15min, Path=/
           - `RefreshToken`: value = refreshToken, HttpOnly=true, Secure=true, SameSite=Strict, Expires=7 days, Path=/
         - Return 200 with `AuthResponse { Email = user.Email, IsAdmin = user.IsAdmin }`

       - **POST /refresh** (per D-06):
         - Read `RefreshToken` from `Request.Cookies`
         - If null/empty: return 401

         - Create new refresh token record in DB
         - Set new cookies (same options as login)
         - Return 200 with `AuthResponse { Email = user.Email, IsAdmin = user.IsAdmin }`

       - **POST /logout**:
         - Require `[Authorize]` attribute
         - Read `RefreshToken` from `Request.Cookies`
         - If found and not revoked: mark `IsRevoked = true`, update
         - Clear both cookies via `Response.Cookies.Delete("AccessToken")` and `Response.Cookies.Delete("RefreshToken")`
         - Return 200 Ok

## Trust Boundaries

|----------|-------------|
| Browser → AuthController | Untrusted user input crosses HTTP boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | GET/POST to auth endpoints | mitigate | POST-only mutations; [Authorize] on logout; FluentValidation on all input |
| T-02-02 | Spoofing | Refresh token replay | mitigate | Rotation on each use (D-05); DB validation of IsRevoked + ExpiresAt |
| T-02-03 | Information Disclosure | JWT in logs | mitigate | Serilog destructuring; never log cookie/header token values |
| T-02-04 | Tampering | JWT theft via XSS | mitigate | httpOnly cookies (D-04) prevent JS access; Secure=true in production |
| T-02-05 | Spoofing | Weak password brute force | mitigate | ASP.NET Identity lockout defaults; password policy 8+ chars + digit + letter (D-17) |
| T-02-06 | Spoofing | CSRF on auth mutations | mitigate | POST-only; SameSite=Lax cookies; no GET-based state mutations |
| T-02-07 | Elevation of Privilege | Non-admin registering as admin | mitigate | Register endpoint always sets IsAdmin=false; only AdminSeeder can create admins |
| T-01-SC | Tampering | NuGet package installs | mitigate | Official Microsoft packages via nuget.org; versions pinned in .csproj |
</threat_model>
